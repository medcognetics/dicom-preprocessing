# Synthetic verification corpus

All DICOMs in this directory are synthetic and released under this repository's
MIT license. No clinical files or patient data were used. Files are embedded in
the Rust library, Python extension, and Node module with `include_bytes!`.

Regenerate from the repository root:

```sh
uv run --script scripts/ci/generate_verification_fixtures.py
```

The script pins pydicom 3.0.2, NumPy 2.4.6, and imagecodecs 2026.3.6. HTJ2K generation
uses OpenJPH `ojph_compress` 0.27.4, installed separately **only for regeneration**.
No runtime verification step invokes this script or any external encoder.

`manifest.json` records syntax UIDs, tag values, every expected sample, and lossy
absolute-error bounds. Pixel expectations come from explicit arithmetic patterns,
not the Rust decoder. RLE uses literal PackBits runs. JPEG lossless uses a minimal
SOF3 stream with a fixed Huffman table and predictor 1; restart interval 4 resets prediction at each
4-pixel row, covering the patched decoder's restart-boundary regression.

JPEG baseline and 12-bit extended use imagecodecs' JPEG encoder. `jpeg-extended-37x23`
spans 5 x 3 blocks with partial edge blocks at quality 95. libjpeg-turbo's own decode
differs from its samples by at most 8, so its tolerance is 9. JPEG 2000 uses
its OpenJPEG encoder. The Part 2 UIDs use compatible single-component codestreams;
they do not exercise arbitrary multi-component transforms. HTJ2K uses real HT
codeblocks generated by OpenJPH, with RPCL progression. Lossy cases compare to
source samples within the explicit manifest tolerances and still require exact
repeatability within the running process.

Keep each UID's static fixture even when the runtime generator covers the same
syntax. An encode/decode round trip alone can hide matching encoder and decoder
errors. Never change expected samples to agree with an incorrect decoder.
